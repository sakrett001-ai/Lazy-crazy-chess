# Browser Lab

Небольшой стенд для проверки 3D-страниц в настоящем Chromium. Он запускается
отдельно от браузера чата и оставляет проверяемый результат: JSON, HTML-отчёт,
скриншоты и трассу при ошибке. Версия 0.1.0.

## Что проверяет первая версия

1. Создаёт WebGL2-контекст, компилирует шейдеры, рисует треугольник и проверяет
   полученные пиксели. В программном режиме требует именно SwiftShader.
2. Запускает пример Anatomy: деформируемая поверхность и рукоять. Проверяет
   правильный контакт и намеренный зазор 40 мм до, на и после границ события.
3. Проверяет, что холсты содержат изображение, две сцены визуально различаются,
   смена времени меняет позу, а возврат к прежнему времени восстанавливает кадр.
4. Считает ошибкой исключения JavaScript, ошибки консоли и внешние сетевые
   зависимости тестовой сцены. Повторный запуск не скрывает первый сбой.

Это проверка стенда и небольшого примера с одной костью. Она **не подтверждает**
качество человеческой модели, баланс персонажа, отсутствие всех пересечений,
состояние всей шахматной игры или работу на телефоне. Для этого нужны отдельные
сценарии проекта. Числа контактов проверяются в браузере; пиксельные проверки
дополняют их, но не являются независимым измерением геометрии шейдеров.

## GitHub Actions

Рабочий процесс находится в `.github/workflows/browser-lab.yml` в корне
репозитория. Для первого запуска достаточно открыть pull request с этим
комплектом. PR-запуски ограничены изменениями самого стенда и его workflow.
После включения workflow в основную ветку доступен ручной запуск:
**Actions → Browser Lab → Run workflow**.

Результат находится в артефакте `browser-lab-<run id>-<attempt>`. Срок хранения
7 дней. После скачивания откройте `html/index.html`; сводка для автоматического
разбора находится в `results.json`. Дополнительные вложения лежат рядом с
HTML-отчётом и в `results/`. Для хранения дольше недели нужные результаты
следует скачать. Скриншоты и журнал видны людям с доступом к артефактам этого
репозитория; текущие примеры не содержат пользовательских данных.

Установлен общий лимит тестов 3 минуты и лимит всей CI-задачи 12 минут.
При ошибке проверки отчёт сохраняется; принудительная отмена или остановка
самого runner может помешать выгрузке. `input.json` и `fixture.json` фиксируют
хеши входов, **не означают успешного теста**. Итог определяют статус задачи и
`results.json`; отсутствие этого файла означает незавершённый браузерный прогон.

Задача использует стандартный runner GitHub. Применяются текущие квоты и
тарифы аккаунта; комплект не покупает ресурсы и не меняет лимиты расходов.

## Локальный запуск

Нужны Node.js 22+ и среда, в которой разрешён запуск Chromium.
Из каталога `tools/browser-lab`:

```sh
npm ci
npx playwright install --with-deps chromium
npm run record
npm run test:logic
npm test
npm run report
```

Проверка структуры без запуска браузера: `npm run test:list`.
Это **не** подтверждение работы WebGL.

## Docker, в том числе на отдельном VPS

Нужен Linux x86-64 с Docker. Выполните из каталога стенда:

```sh
sh scripts/docker-check.sh
```

Скрипт собирает образ, выполняет проверку и копирует результат в
`evidence/docker-<время>/`. Контейнер после этого удаляется. Во время сборки
нужен доступ к реестрам Microsoft и npm. Во время теста сеть контейнера
отключена; тестовая страница и браузер общаются внутри него через loopback.
Порты наружу не публикуются. Ограничения: 2 CPU, 3 ГБ памяти, 1 ГБ shared memory.
Это стартовая конфигурация, не замер потребностей большого проекта.

Этот комплект выполняет доверенные локальные тесты и использует обычный
тестовый режим Playwright. Он не предназначен для посещения произвольных
сайтов или работы с личными браузерными профилями. Ничьи ключи, cookies и
Docker-сокет в контейнер не передаются. Настройки среды ChatGPT не изменяются.

## Как подключать следующие проекты

Скопируйте `tools/browser-lab` и workflow в репозиторий проекта. Workflow
ожидает именно этот путь. Создайте отдельную подготовленную сцену в `fixtures/`
и тест в `tests/`; добавьте его отдельным проектом в `playwright.config.mjs`
с зависимостью `webgl`. Сначала определите проверяемые положения камеры,
временные точки и ожидаемые измерения. Готовность сцены должна подтверждаться
её сигналом после загрузки ассетов, а не фиксированной задержкой.

Изменения навыков автоматически не копируются: `fixtures/source` — снимок
примера. Для проверки новой версии навыка обновите этот снимок, происхождение
в `fixtures/provenance.json` и выполните новый прогон. Успешный старый отчёт
не подтверждает изменённый код.

Проекты со сборкой, авторизацией, backend или внешними ассетами требуют своего
адаптера и правил доступа. Нынешний сервер обслуживает только `fixtures` и
слушает `127.0.0.1`; доступ к каталогу проекта целиком ему не нужен.

## Изображение и производительность

По умолчанию `QA_RENDERER=software`: Chromium использует SwiftShader. Такая
отрисовка позволяет проверять изображение без GPU, но не измерять реальные
FPS игры. `QA_RENDERER=native` убирает выбор SwiftShader; фактический renderer
нужно проверить в `webgl.json`. Само название режима не доказывает наличие
видеокарты. Никаких обещаний «60 FPS» на основе этого стенда нет.

## Основания и версии

- [Playwright CI](https://playwright.dev/docs/ci): запуск, отчёты и таймауты.
- [Playwright Docker](https://playwright.dev/docs/docker): образ и соответствие версии пакета браузерам.
- [Chromium SwiftShader](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md): программная отрисовка через ANGLE.

Playwright 1.64.0, образ `mcr.microsoft.com/playwright:v1.64.0-noble`.
Three.js 0.180.0 соответствует исходному примеру. Зависимости зафиксированы
в `package-lock.json`. Версии GitHub Actions закреплены по major; это не
побайтовая фиксация всей внешней цепочки. Three.js распространяется по MIT;
его лицензия включена в `THIRD_PARTY_NOTICES.md`.
