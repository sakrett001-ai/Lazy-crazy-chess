# Белая пешка во Floot

Репозиторий: `sakrett001-ai/Lazy-crazy-chess`, исходная ветка `main`.
Проект Floot: `5311a72f-aeb2-4bc4-94ea-e491870d0b13`.
Адрес приложения: [lazy-crazy-chess.floot.app](https://lazy-crazy-chess.floot.app). Оболочка опубликована во Floot; её обновление выполняется отдельно от выпуска просмотрщика.

## Два независимых вида просмотра

`prototypes/white-pawn/white-pawn.html` — автономный HTML с моделью и изображением внутри. Он остаётся доступен для открытия без сети.

Размещённый просмотр — компактный HTML с интерфейсом и Three.js внутри. Модель и изображение он получает из этого же публичного репозитория по неизменяемому адресу конкретного коммита. Холодный запуск требует сети. Перед открытием GLB проверяется SHA-256; при несовпадении модель не запускается и непроверенный файл не предлагается для скачивания.

Текущие исходники и локальная сборка: интерфейс `0.4.0`, модель `0.3.0`. Это прототип для примерки с [известными ограничениями](INFANTRY_V03_REVIEW.md): в некоторых крайних позах остаются пересечения одежды и неполное смыкание пальцев. Действующую версию сайта определяют manifest в `gh-pages` и строка версии на сайте. Клипы `Shield_Brace` («Упор щитом») и `Spear_Study` («Учебный укол») сохраняют имена и длительность по 4 с. Новые позы двуручного оружия вычисляет `src/loadout.mjs` после выборки исходного клипа; они не запечены в GLB.

[Структурный отчёт](../prototypes/white-pawn/assets/model-checks.json), [проверка движения экспортированных поверхностей](../prototypes/white-pawn/review/equipment-checks.json) и [геометрический аудит](../prototypes/white-pawn/review/geometry-checks.json) описывают точную модель, указанную в их SHA. [Приёмка 0.2.0](WHITE_PAWN_V02_REVIEW.md) хранится отдельно как история. Проекция таза на контур подошв служит геометрическим показателем опоры, без расчёта центра масс и физического баланса. Продвижение оружия наконечником вдоль оси подтверждает траекторию анимации, без моделирования сил удара. Проверки просмотрщика подтверждают загрузку, целостность и управление; локальный аудит поверхностей и визуальную приёмку они не заменяют.

Версия интерфейса берётся из `prototypes/white-pawn/package.json`; версия модели задаётся `MODEL_VERSION` в `scripts/release-utils.mjs`. Автономный просмотр использует те же номера в `src/viewer.mjs`. Manifest и строка версии различают эти два номера; замечания дополнительно привязаны к точному SHA-256 GLB.

## Как приходит обновление

1. Изменения появляются в `main`.
2. `.github/workflows/publish-pawn.yml` устанавливает зависимости по lock-файлам **обоих** пакетов: `human-base` и `white-pawn`. Он проверяет снаряжение и движения конечного GLB (`verify:equipment`) и выполняет CPU-проверку геометрии (`verify:geometry`). Затем выполняет тесты правил публикации, собирает автономный просмотр и проверяет его управление, профили (`verify:appearance`) и варианты (`verify:variants`).
3. `build:hosted` создаёт кандидат HTML без manifest релиза. `verify:hosted` проверяет загрузку, управление, экран 390 px, отказ при изменённом GLB и недоступном сервере, а также запасной режим без WebGL.
4. Только `release:hosted` создаёт `chess-release.json` со статусом `checks: passed`. Требуются успешные структурный отчёт Blender, проверки оборудования, геометрии, вариантов, профилей и просмотрщиков. Все отчёты привязаны к текущему GLB; браузерные — также к точным проверенным HTML. `geometry-checks.json` дополнительно содержит `runtimeSha256` точных байтов `src/loadout.mjs`: изменение вычисляемых поз требует повторной проверки даже при прежнем GLB. Workflow запускает CPU-аудит геометрии; структурный отчёт Blender сохраняется в исходном коммите и проверяется по SHA. Это конечная выборка поз и контактов, а не физика боя или непрерывная гарантия отсутствия пересечений. Устаревшие отчёты не дают создать manifest. Обычный путь требует успешного геометрического отчёта; ограниченный путь для прототипа описан ниже.
5. Workflow повторно сверяет `main` с исходным коммитом и обычным fast-forward push добавляет в `gh-pages` только manifest и `chess/releases/<sourceCommit>/viewer.html`. Корневые страницы, прежние релизы и другие разделы не заменяются. PR проходят проверки без публикации.
6. Оболочка Floot получает manifest из `gh-pages`, проверяет его поля, размер и SHA-256 HTML. Просмотр запускается на домене Floot; сам GLB дополнительно проверяет браузер.

Это мост проверенных релизов. Изменение ядра просмотрщика не требует повторной публикации оболочки Floot. Изменения самой оболочки или её серверного обработчика нужно отдельно перенести и опубликовать через Floot. Текущая открытая страница не заменяет модель во время осмотра; новый релиз применяется после открытия или перезагрузки.

## Состав релиза

`gh-pages/chess-release.json` содержит `schemaVersion`, фиксированный `repository`, `sourceBranch: main`, полный `sourceCommit`, `version`, `modelVersion`, `checks`, `builtAt` и `document: {path, sha256, bytes}`.

HTML меньше 2 МБ и содержит `window.PAWN_HOSTED`: `modelUrl`, `modelSha256`, `posterUrl`, `version`, `modelVersion`, `sourceCommit`. URL модели и изображения закреплены за полным SHA коммита в `raw.githubusercontent.com`; ссылки на меняющуюся ветку не используются.

Бинарная модель и изображение не дублируются в `gh-pages`. Их исходные файлы остаются в `prototypes/white-pawn/assets/white-pawn.glb` и `prototypes/white-pawn/review/neutral.png` соответствующего коммита `main`.

## Локальная проверка

Из корня репозитория:

```bash
npm ci --prefix prototypes/human-base
npm ci --prefix prototypes/white-pawn
cd prototypes/human-base
npx playwright install chromium
cd ../white-pawn
npm run test:release
npm run verify:equipment
npm run verify:geometry
npm run build
npm run verify
npm run verify:appearance
npm run verify:variants
npm run build:hosted
npm run verify:hosted
npm run release:hosted
```

Эти команды используют уже собранные GLB, рендер и структурный отчёт. При изменении геометрии сначала запустите `scripts/build_modular.py` и `scripts/model_checks.py` в среде Blender Python; [подготовка и команды](../prototypes/white-pawn/README.md#пересобрать-модульную-модель). Старые отчёты не заменяют новую проверку.

Выходные файлы размещённого просмотра находятся в `dist/` корня репозитория; автономный HTML — в `prototypes/white-pawn/white-pawn.html`. `chess-candidate.json` и `dist/review/` — местные данные проверки; в опубликованный релиз они не входят. Перед `build:hosted` исходники и модель должны быть сохранены в коммите: адрес GLB проверяется против содержимого указанного коммита. Сам локальный запуск ничего не отправляет в GitHub или Floot.

Если проверка или workflow не прошли, ранее опубликованный manifest в `gh-pages` остаётся без изменений. Локальная неудачная сборка удаляет старый manifest из `dist/`, чтобы его случайно не приняли за новый проверенный релиз. Для возврата к прежнему поведению можно сделать обычный revert в `main` и провести его через тот же цикл.

Модель 0.2.1 меняла только материалы, поэтому тогда допускался доказанный перенос прежнего аудита. Модульная модель 0.3.0 меняет геометрию: прежний аудит 429 поз не наследуется. [Настройки и ограничения экспорта](WHITE_PAWN_CUSTOMIZATION.md).

Если GitHub Actions не запускается из-за ограничений учётной записи, завершённые локальные проверки можно использовать для ручной публикации тех же файлов через GitHub. Такой выпуск сохраняет проверки SHA и ожидаемого HEAD; он не означает, что автоматический запуск Actions исправлен.

## Выпуск прототипа с известными пересечениями

Версия 0.4.0 использует явное решение `review/geometry-acceptance.json`, привязанное к SHA модели, модуля движения и полных байтов геометрического отчёта. Оно разрешает только зафиксированные пересечения слоёв одежды; ошибки структуры, нечисловые координаты, неправильный хват, опора или контрольные проверки не допускаются. Решение Codex не является подтверждением пользователя.

Геометрический отчёт остаётся `failed`. Manifest сохраняет `geometryStatus`, `geometryDecision` и `geometryLimitations`; поле `checks: passed` означает прохождение правил выпуска прототипа, а не отсутствие пересечений. В интерфейсе показаны ограничения. Автоматический workflow по-прежнему останавливается на `verify:geometry`; этот выпуск выполняется вручную после остальных проверок, с проверкой хешей и ожидаемых HEAD обеих веток.
